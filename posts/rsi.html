RSI到底是什么

2026年8月18日

AI 改进自己，当然是要变得越来越强。问题是，强到底是什么。

对照人类会比较直观。人当然希望自己算得更快，但更重要的是，对世界的认知越来越丰富：给定差不多的信息和资源，以前只能想到三件事，现在能想到十件事；以前看不懂别人的表情，现在能捕捉到；以前只能等别人把需求说出来，现在能提前猜到。科研也是一样，一个研究者真正的进步，并不只是解题速度更快，而是以前意识不到的问题现在能够意识到，以前无法建立联系的东西现在能够建立联系。

这些东西不一定都容易验证。拉马努金写下公式的速度远远超过证明速度，一个新的数学理论也可能需要同行花很多年才能判断到底对不对。所以“能力提高”和“人类能够廉价验证能力提高”本来就是两件不同的事情。RSI 的困难也正是从这里开始。

AI 的算法当然是核心，但今天的 LLM Agent 不一定首先修改模型权重。Prompt、工具、上下文管理、记忆、搜索、reviewer、planner、代码结构，甚至“什么时候修改这些东西”的规则，本身都属于系统。可以把时刻 \(t\) 的完整机器记成 \(C_t\)，而机器内部负责产生下一版本的过程记成 \(M_t\)，于是有

\[ C_{t+1}=M_t(C_t,H_t), \]

其中 \(H_t\) 是机器此前积累的运行历史、实验结果和外部反馈。 如果只是 \(C_{t+1}\) 在某个 benchmark 上比 \(C_t\) 好，当然已经发生了 self-improvement。但 recursive 真正有意思的地方，不只是机器能修改自己的代码，而是 \(M_t\) 本身也属于 \(C_t\)。也就是说，机器不只是修改 solver，它还可以修改“自己应该怎样寻找下一次修改”。

所以真正值得关心的并不只是这一代 Agent 有多强，还包括它作为一个祖先有多强。一个现在得分稍低、但给它相同计算预算以后能够不断产生更好后代的 Agent，可能比一个已经针对当前 benchmark 优化到极致、以后却很难继续提升的 Agent 更重要。Huxley-Gödel Machine 所强调的 metaproductivity，大致就在问这个问题。

最简单的 RSI 实验当然可以从固定任务集开始。设 \(\mathcal{T}=\{\tau_1,\ldots,\tau_n\}\)，再定义一个评价函数 \(J(C)\)，把完成任务需要的 wall-clock time、计算量、token 消耗、失败惩罚等等放进去。系统从 \(C_0\) 开始，可以任意修改自身。如果不断出现 \(J(C_{t+1})<J(C_t)\)，那么至少可以说，它正在这个任务集上改进自己。

甚至可以提出一个更强的理想条件：假设机器和环境参数都已知，对一个新的有限任务集存在某种最优系统，那么机器能不能从任意一个非最优版本开始，通过修改包括自我修改算法在内的全部代码，在有限步骤以后逼近这个最优系统？

这个定义看起来很漂亮，但问题也马上出现。固定任务集终究会被吃干净。机器可以把 benchmark 做到极高，却不意味着它对世界的认知继续扩大。更重要的是，人类真正关心的知识根本无法提前写进一个有限任务集。我们已经提出的问题只是很小的一部分，还有人类正在研究而不会解决的问题，更有一些问题是我们今天根本不知道应该怎么问的。

所以任务集必须动态变化。

一种办法是人类继续扩充任务集。机器解决当前任务，人类根据自己的需求再提出下一批问题。这样当然最安全，但机器的知识增长速度永远受限于人类提出问题的速度。另一种办法是机器自己扩充任务集。机器不仅回答问题，还开始猜测“下一个值得回答的问题是什么”，然后再让机器、人类或者现实环境去验证这些新问题有没有意义。

后一条路明显危险得多。机器完全可以发明大量看似新颖、实际上毫无价值的问题。但如果我们希望 RSI 最终超过人类已有知识的边界，又几乎绕不开它。因为机器只有开始主动构造未知，人类想象力才不再成为它的上限。

不过这里不能简单假设知识和任务一一对应。

一个牛顿力学模型可以解决无穷多个初始条件不同的问题；反过来，两套内部完全不同的世界模型，也可能在现有一万个测试题上给出完全相同的答案。所以任务更像是探测知识的实验，而不是知识本身。

假设机器当前内部存在某种知识状态 \(K_t\)。如果两个知识状态 \(K_1\) 和 \(K_2\) 在当前所有任务上都给出相同结果，那么对当前任务集 \(\mathcal{T}_t\) 来说，我们根本区分不了它们，可以暂时写成 \(K_1\sim_{\mathcal{T}_t}K_2\)。 这时候，增加新任务真正有意义的地方，不是让 \(|\mathcal{T}_t|\) 变大，而是找到一个新的任务 \(\tau\)，让原本无法区分的两个知识假设出现不同结果。

这样一来，“机器自己扩充任务集”就不应该理解成不停制造更多题目。把一道数学题的数字换一万次，并没有增加一万倍知识。真正好的新任务，应该能够暴露机器认知边界，或者排除某些错误模型，或者一旦解决以后能够同时解锁一大批其他任务。

于是机器需要的不只是一个 solver，还需要一个 task proposer。可以把它记成 \(Q_t\)。它根据机器已有的知识和历史，提出下一批可能值得探索的任务：

\[ Q_t:(K_t,H_t)\rightarrow \tau. \]

一个好的 \(Q_t\)，本质上是在寻找“哪里最值得不知道”。它可能寻找机器现在做不到、但经过有限学习应该能够做到的问题；可能寻找几个竞争模型预测差异最大的位置；也可能寻找解决以后能够产生大量下游能力的问题。

这个过程其实已经很接近科学研究。科学家不是为了把实验数量做大，而是希望设计一个实验，让错误的解释暴露出来。

于是 RSI 从“机器会不会解决任务”，进一步变成“机器会不会发现值得解决的新任务”。

但这马上又带来另一个问题：谁来判断机器自己提出的任务到底有没有价值？谁来判断它声称自己解决了一个新问题以后，是真的获得了新知识，而不是把 evaluator 骗过去了？

这就是验证成本。

假设机器能力不断增长，那么真正的瓶颈很可能会从“机器做不出来”逐渐变成“人类验不过来”。验证成本可以粗略写成

\[ C_{\text{verify}}=\sum_i c_i+\lambda T_{\text{wall}}+C_{\text{coord}}. \]

其中既有人真正花掉的劳动，也有等待验证结果需要的时间，还有大量人协调时产生的成本。

让更多用户同时参与，可以降低 wall-clock time；形式化工具则可能降低单次验证成本。Lean 一类形式系统真正特别的地方，不是让发现证明变得简单，而是把“发现一个证明”和“检查一个证明”拆开。前者可以非常昂贵，后者却可以极其便宜。一旦某个复杂结果被转化成机器可以廉价重复检查的形式，之后的验证成本就会突然下降。

所以真正的 RSI 不应该只是扩大机器解决问题的能力，还应该扩大机器验证问题的能力。 一个今天需要三个专家讨论两天才能确认的结果，机器以后也许可以先把它转成明确实验；再往后转成形式化规范；最后变成一个几秒钟就能完成的机器检查。这里发生的不只是知识增长，而是验证本身被压缩了。

这会形成一个非常重要的正反馈。机器越强，越能找到新的知识；新的知识越多，越需要更便宜的验证；机器于是开始改进 verifier；verifier 变强以后，机器又能够更快试验下一批想法。 但 verifier 一旦可以修改，危险也马上出现。

固定 evaluator 会成为机器优化的目标。机器越来越强以后，很可能不是继续理解世界，而是越来越擅长找到评分规则的漏洞。所以 Red Queen Gödel Machine 之类的思路会让 evaluator 也参与演化。

可如果 solver 和 evaluator 同时完全自由地变化，问题甚至更严重。机器可以自己发明任务、自己修改评分标准，再自己宣布自己取得巨大进步。整个内部系统越来越一致，却可能越来越偏离现实。

因此人类不应该继续负责提出机器的所有任务，但也不能完全退出。

更合理的结构可能是：机器高速生成任务，机器高速验证绝大部分结果，人类只对其中极少量高价值、高不确定性或者 verifier 发生冲突的部分进行抽查。这样，人类从“给机器出每一道题的人”，逐渐变成“校准什么算有意义的人”。

这里的人类其实是一条低带宽但不能断掉的 grounding channel。

做到这里，一个完整的 RSI 系统就不只是 Agent 本身了。至少可以粗略拆成几部分：\(S_t\) 负责解决问题，\(Q_t\) 负责提出新问题和新环境，\(V_t\) 负责验证，\(R_t\) 负责把经验压缩成模型、skill 和抽象，而 \(M_t\) 负责修改前面所有这些东西，也包括修改自己。

所以可以暂时写成

\[ C_t=(S_t,Q_t,V_t,R_t,M_t). \]

这只是为了把问题拆开，不意味着最后的软件一定真有五个独立模块。真正重要的是，这五种功能都会成为自我改进的对象。其中 \(R_t\) 很容易被忽略，但它可能非常重要。知识增长并不意味着机器永远保存更多原始信息。人类恰恰会不断遗忘细节，把过去的经历压缩成新的抽象。几十次社交经验最终可能只留下一个感觉：“对方说话开始明显变短的时候，大概应该结束这个话题了。”

所以历史经验可以不断增加，但当前知识表示不一定越来越大。可以让累计历史 \(\overline{\mathcal{T}}_t\) 保持增长：

\[ \overline{\mathcal{T}}_{t}\subseteq\overline{\mathcal{T}}_{t+1},\qquad K_t=R_t(\overline{\mathcal{T}}_t). \]

机器真正变强，甚至可能意味着 \(K_t\) 变得更简单。原来需要记住一万个局部规律，现在找到了一个统一结构，一条规则就能生成大量以前分别记忆的行为。知识增长和压缩并不冲突，好的知识本来就是一种压缩。

那么最后到底应该如何比较机器和人类？ 简单比较“机器任务集是不是比人类任务集大”没有意义，因为任务粒度可以任意改变。一万个换数字的问题，并不一定比一个新理论包含更多知识。

更合理的东西应该是能力边界。

可以先不用特别复杂的公式，只定义 \(\mathcal{T}(C,b)\) 表示系统 \(C\) 在资源预算 \(b\) 下能够稳定完成的任务集合。那么机器变强至少有两种表现：在相同预算 \(b\) 下，\(\mathcal{T}(C,b)\) 越来越大；或者对于同一个任务，机器需要的最小预算越来越低。

人的能力域可以写成 \(\mathcal{T}_h(b)\)，机器的能力域写成 \(\mathcal{T}_m(b)\)。如果在人类关心的大部分任务上，机器都已经能够用相似甚至更少的资源完成，那么可以说机器覆盖了很大一部分人类已有能力。 但真正重要的反而是机器能力域超出人类能力域的部分。

那里可能存在机器会做、人类不会做的问题，更可能存在人类今天甚至不知道怎么描述的问题。于是机器不能只是冲进这些未知区域，然后告诉我们“相信我，我发现了很多东西”。它还需要不断修建一条返回人类世界的路径：把原本无法理解的结果转成实验、预测、证明、产品或者某种人类能够验证的后果。

如果这条路径完全断掉，我们甚至无法判断机器究竟获得了超人知识，还是只进入了一个无法被外界检验的内部循环。

所以 RSI 最终优化的恐怕根本不是一个固定的 \(J(C)\)。 真正重要的是几个过程同时越来越快：相同资源下能够完成的任务越来越多；给定相同自我改进预算，产生优秀后代的概率越来越高；提出的新任务越来越能够暴露真正未知；过去昂贵的验证不断被压缩成廉价验证；大量旧经验又不断被压缩成更短、更一般的知识结构。

机器解决一个新问题，暴露新的未知；新的未知让它提出新的实验；实验产生新的知识；知识被压缩以后，又让 solver 和 proposer 变强；机器同时改进 verifier，降低下一轮试验成本；这些结果最后又反过来改进负责整个自我修改过程的 \(M_t\)。

所以真正的 recursive，不只是代码能够修改代码。 它应该是发现、学习、抽象、验证、自我修改这一整条知识生产链，本身也开始越来越高效。

这样看，RSI 最终要学会的不是某一个固定目标函数，而是一种扩张方式：知道自己现在会什么，知道什么地方值得探索，知道怎样设计实验暴露未知，知道怎样把新知识压缩进自己，也知道怎样让未来的自己或者人类更便宜地确认这次发现是真的。

如果这个过程能够长期稳定持续，那么人与机器真正拉开的差距，就不再只是“谁知道的答案更多”，而是谁能更快地产生下一批值得知道的东西。
